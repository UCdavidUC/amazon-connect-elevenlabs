Integración de Amazon Connect con ElevenLabs TTS y Amazon Lex con Bedrock RAG para Centro de Contacto Inteligentes

DL
David S.
Publicado el 5 de mayo de 2026 | Tiempo de lectura: 15 minutos

Los Centros de Contacto modernos enfrentan un desafío constante: ofrecer experiencias de voz naturales y personalizadas mientras mantienen la eficiencia operativa. En este post, mostramos cómo integrar Amazon Connect con ElevenLabs para text-to-speech con personalización de voz y Amazon Lex con Bedrock RAG para respuestas inteligentes basadas en una base de conocimiento.

Esta solución permite que un asistente virtual atienda llamadas con una voz similar a la humana, responda preguntas usando Retrieval-Augmented Generation (RAG) con Amazon Bedrock, y escale a agentes humanos cuando sea necesario.

Cómo funciona

  1. El usuario llama al número telefónico de Amazon Connect.
  2. Set Voice configura ElevenLabs como el motor TTS para todo el flujo.
  3. Play Prompt reproduce el mensaje de bienvenida con la voz de ElevenLabs.
  4. Get Customer Input escucha al usuario y envía el audio a Amazon Lex.
  5. Lex + Bedrock RAG procesa la pregunta, consulta la Knowledge Base, y genera una respuesta.
  6. Connect reproduce la respuesta usando la voz de ElevenLabs.
  7. El flujo regresa al paso 4 (loop conversacional) hasta que el usuario se despida o pida transferencia.

Prerrequisitos

  • Cuenta de AWS con Amazon Connect, Amazon Lex V2 y Amazon Bedrock habilitados
  • Cuenta de ElevenLabs con subscripción (mínimo Starter, $5 USD/mes)
  • AWS CDK v2 instalado
  • Node.js 18+ y npm
  • Una base de conocimientos en Bedrock Knowledge Base configurada con tus documentos

Paso 1: Desplegar la infraestructura con CDK

El stack de CDK despliega los recursos de seguridad necesarios: una KMS key de cliente y la configuración de Secrets Manager para almacenar la API key de ElevenLabs de forma segura.

# Clonar el repositorio e instalar dependencias
cd connect-elevenlabs
npm install

# Configurar variables de entorno
cp .env.example .env
# Editar .env con tus valores

# Desplegar
npx cdk bootstrap   # Solo la primera vez
npx cdk deploy
Nota: Formato del secreto Amazon Connect espera que el secreto en Secrets Manager tenga el formato JSON: {"apiToken": "sk_tu_api_key"}. Un formato incorrecto genera el error "The secret could not be deserialized".

Configuración del secreto

# Crear o actualizar el secreto con el formato correcto
aws secretsmanager put-secret-value \
  --secret-id elevenlabs-connect/api-key \
  --secret-string '{"apiToken":"sk_TU_API_KEY_AQUI"}'

# Re-cifrar con la KMS key de cliente (del output de CDK)
aws secretsmanager update-secret \
  --secret-id elevenlabs-connect/api-key \
  --kms-key-id TU_KMS_KEY_ID

Política de recursos del secreto

aws secretsmanager put-resource-policy \
  --secret-id elevenlabs-connect/api-key \
  --resource-policy '{
    "Version": "2012-10-17",
    "Statement": [{
      "Effect": "Allow",
      "Principal": {"Service": "connect.amazonaws.com"},
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "*",
      "Condition": {
        "ArnLike": {"aws:sourceArn": "CONNECT_INSTANCE_ARN"},
        "StringEquals": {"aws:sourceAccount": "ACCOUNT_ID"}
      }
    }]
  }'

Paso 4: Asignar número telefónico y probar

  1. En Connect admin → Channels → Phone numbers
  2. Selecciona tu número → asigna el flujo ElevenLabs Lex RAG Flow
  3. Llama al número y verifica:
    • La bienvenida se escucha con voz ElevenLabs
    • Las preguntas se responden correctamente con RAG
    • El loop conversacional funciona (puedes hacer múltiples preguntas)
    • "Adiós" termina la llamada
    • "Quiero hablar con una persona" transfiere a la cola

Conclusión

Esta integración demuestra cómo combinar lo mejor de AWS y ElevenLabs para crear experiencias de contact center que son tanto inteligentes como naturales. Amazon Connect maneja la telefonía, ElevenLabs proporciona voces de calidad humana, y Lex con Bedrock RAG entrega respuestas precisas basadas en tu base de conocimiento.

El patrón de loop conversacional — donde la rama FallbackIntent regresa al mismo bloque Get Customer Input — es simple pero poderoso. Permite conversaciones multi-turno sin necesidad de Lambda functions intermedias, reduciendo latencia y complejidad.

Para escenarios que requieren mayor control sobre la lógica conversacional, herramientas personalizadas, o la inteligencia del agente de ElevenLabs, consulta el Escenario 2 que utiliza un agente conversacional de ElevenLabs con un puente Lambda WebSocket.
