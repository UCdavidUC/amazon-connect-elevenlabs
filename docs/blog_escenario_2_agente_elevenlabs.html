Integración de Amazon Connect con Agente Conversacional ElevenLabs mediante Lambda WebSocket Bridge

DL
David L.
Publicado el 5 de mayo de 2026 | Tiempo de lectura: 20 minutos

En este post presentamos una arquitectura avanzada que conecta Amazon Connect con un agente conversacional de ElevenLabs a través de una función Lambda que actúa como puente WebSocket. A diferencia del enfoque con Lex + Bedrock RAG, aquí el agente de ElevenLabs maneja toda la lógica conversacional, incluyendo base de conocimiento, herramientas (webhooks) y manejo de contexto multi-turno.

Esta solución es ideal cuando necesitas conversaciones complejas con acciones en tiempo real (consultar pedidos, crear tickets, agendar citas) y quieres aprovechar la plataforma de agentes de ElevenLabs junto con su voz de alta calidad.

Como funciona el puente WebSocket

La funcion Lambda actua como intermediario entre Amazon Connect y el agente de ElevenLabs:

  1. Connect invoca la Lambda con la transcripcion del usuario (obtenida via Lex passthrough).
  2. La Lambda obtiene la API key de Secrets Manager.
  3. Solicita una signed URL al API de ElevenLabs.
  4. Abre una conexion WebSocket al agente.
  5. Envia el texto del usuario y espera la respuesta del agente.
  6. Retorna la respuesta a Connect, que la reproduce con voz ElevenLabs.

Paso 1: Configurar el agente en ElevenLabs

Crear el agente

  1. Ve a https://elevenlabs.io/app/conversational-ai
  2. Haz clic en Create Agent
  3. Configura nombre, voz e idioma (Spanish)

System Prompt recomendado

Eres un asistente virtual profesional de [Empresa].
Tu nombre es [Nombre].

Rol:
- Responder preguntas sobre productos y servicios
- Resolver problemas comunes
- Recopilar informacion para tickets de soporte
- Transferir a un agente humano cuando no puedas resolver

Lineamientos:
- Responde siempre en espanol de Mexico
- Maximo 2-3 oraciones por respuesta (es una llamada telefonica)
- Si no sabes algo, dilo honestamente
- Usa transfer_to_agent cuando el usuario pida un humano
- Usa end_conversation cuando el usuario se despida

El stack despliega:

  • KMS Key con politica para Amazon Connect
  • Lambda Function (Node.js 22, ARM64) como puente WebSocket
  • Lex Bot passthrough para capturar voz libre

Post-despliegue: asociar recursos con Connect

  1. Consola de Amazon Connect → tu instancia → AWS Lambda → agregar la funcion bridge
  2. Misma pagina → Lex bots → agregar ElevenLabsSpeechPassthrough alias live

Conclusion

Este escenario demuestra como aprovechar la plataforma de agentes conversacionales de ElevenLabs dentro de un contact center empresarial basado en Amazon Connect. La funcion Lambda como puente WebSocket permite mantener la arquitectura serverless mientras se accede a las capacidades avanzadas del agente: base de conocimiento, herramientas con webhooks, y manejo de contexto conversacional.

Para casos de uso mas simples donde solo necesitas RAG sobre una base de conocimiento, el Escenario 1 con Lex + Bedrock RAG ofrece menor latencia y complejidad. Elige el escenario que mejor se adapte a tus necesidades de negocio.
